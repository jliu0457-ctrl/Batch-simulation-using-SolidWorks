## 2. 在哪敲命令

**除了 §11 第 1 步（生成数据，在 `数据生成/` 下），其余命令都在 `自动映射/` 下敲。**

```bash
cd "C:\Users\liujunxiang\Desktop\流体仿真2\自动映射"
```

⚠️ 本机 shell 是 **Git Bash**：带 `/开头` 参数的 Windows 命令（比如 §5 的
`tasklist /v /fi ...`）会被 msys 当成路径改写，报 `无效参数/选项 - 'V:/'`。
**前面加 `MSYS_NO_PATHCONV=1`** 即可，或改用 `cmd.exe /c`。

## 3. 跑一个样本：三条命令

⚠️ **跑批量请直接用 §11**，那才是日常用法。这一节是**单样本手工跑法**，
只在排查某一个具体设计点、或想单独看某个样本时才用。

把 `<run>` 换成你起的名字（会建在 `working/seven_variable_trials/<run>/` 下）。

```bash
# ① 生成样本副本（约 80 秒）
#    读：config/design_baseline_v6.json（七变量）
#    写：working/seven_variable_trials/<run>/  ← 一套 CAD 副本
./scripts/Run-OneDesign.exe . <run> config/design_baseline_v6.json

# ② 跑到求解前（约 55 秒）
#    读：上面那套副本
#    写：<run>/flow_sample.json（阶段报告）、<run>/1/（Flow 工程）
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json --execute

# ③ 求解 + 出训练行（约 1 分钟；其中 40 秒是求解本身）
#    写：<run>/training_sample.csv、outputs/training_dataset.xlsx
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json \
       --execute --resume --yes-solve --timeout-min 25
```

**每样本约 3.5 分钟**（实测 175~238 秒）。`<run>` 不能重名（脚本拒绝覆盖）。

⚠️ ② 的耗时**不稳**（实测 54~90 秒）：波动几乎全在 S3 开口识别那一阶段的
COM 枚举上（同样的 448 条边，跨会话能差 20 秒）。③ 不用跑 S3，所以 ③ 很稳。

**只读预检**（不写任何东西，先查环境和输入）：

```bash
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json
```

**任何一步失败**：修好原因后加 `--resume` 接着跑，**不要删目录重来**。

```bash
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json \
       --execute --resume [--yes-solve]
```

## 4. 你会动到的文件

| 文件 | 是什么 | 谁改 |
|---|---|---|
| `config/design_baseline_v6.json` | 一个七变量设计点 | **你**：复制一份、改数值 |
| `config/flow_physics_reference.json` | 边界条件 / 目标 / 网格 / 收敛 / 参考真值 | 只在人工工程有变化时改（见 §8）|
| `working/assembly_batch_v6/` | **V6 母版** | **谁都不许改** |
| `working/seven_variable_trials/<run>/` | 每次跑出来的副本 | 脚本 |
| `outputs/training_dataset.xlsx` | 17 列训练表（追加）| 脚本 |

## 5. 跑之前必须满足（最容易卡在这）

脚本**只「附加」到已经在跑的 SolidWorks，不冷启动它**。

| 条件 | 怎么确认 |
|---|---|
| 手工启动 SolidWorks，停在**空白主界面** | 界面上没有打开的文档 |
| **关掉全部文档** | `Ctrl+W` 逐个关 |
| **只保留一个 `SLDWORKS.exe`** | 见下 |
| 残留的 `~$` 锁文件 | **不用管**，门禁会自己清 |
| 残留的孤儿进程 | **不用管**，`attach()` 会自己清（见下）|

**两个实例怎么办**（Git Bash 里必须加 `MSYS_NO_PATHCONV=1`，否则 `/fi` 被当成路径）：

```bash
MSYS_NO_PATHCONV=1 tasklist /v /fi "IMAGENAME eq SLDWORKS.exe" /fo csv
```

⚠️ 窗口标题**精确等于** `NVOGLDC invisible` 的那个是**孤儿进程**（没有界面、不持有文档）。
`flow_session.attach()` 会在附加前自动清掉它，**你什么都不用做**；
标题正常或状态不明的实例它一律不碰。

## 6. 结果在哪

| 想看什么 | 看哪个文件 |
|---|---|
| 每阶段干了什么、门禁过没过 | `<run>/flow_sample.json` |
| **一行 17 列训练数据** | `<run>/training_sample.csv` + `outputs/training_dataset.xlsx` |
| 停机点 / 逐目标值 / 网格数 | `<run>/1/1.info.json` |
| **逐迭代历史**（排查收敛最有用）| `<run>/1/Goals.DAT/*.txt` |
| 冻结的工程配置 | `<run>/1/1.xmlconfig` |

**17 列 = `样本序号` + 7 个设计变量 + 7 个目标值 + `ΔP` + `Cv`。**

- 那 7 个目标值 = Flow 界面「目标图」里的**「平均值」列**（不是「数值」列）
- **第 1 列 `样本序号`** 批量跑时来自 `Variables/*.xlsx`；单样本跑留空
- **`ΔP` = 入口静压 − 出口静压**（Pa）。它和流量是 Cv 公式的两个输入，
  记下来才能从表里反推 Cv 是怎么算出来的 —— 拿它和流量重算一遍应与 `Cv` 列吻合到 1e-13

## 7. 出问题按这个表查

| 现象 | 处理 |
|---|---|
| `A same-named document is already open` | SolidWorks 里关掉全部文档 |
| 门禁报 `SLDWORKS.exe 实例数 2` | 见 §5 |
| `CO_E_SERVER_EXEC_FAILURE` | 手工启动 SolidWorks，别让脚本冷启动 |
| `拒绝续跑：几何与磁盘不符` | 删掉 `<run>` 重新克隆 |
| 卡住不动、无报错 | 去 SolidWorks 界面看有没有弹模态框，手动关掉 |
| 目标绑不上（`NeedsSeatFaces`）| **先读报错细节再决定。** 若写着「某面是 cone、配置要 plane」→ 这是**该设计点锥角太小、蝶板曲面重排**了（实测 α=23.5° 会中，α=36° 不会），属于**真实失败**、不是配置问题。**不要**用 `--allow-partial-goals` 掩盖 —— 那是"绑不上就跳过、缺列留空"的降级模式，会把真问题藏起来 |

## 10. 数据纪律（别绕过）

- **失败只写报告、不追加数据行** —— 崩了的样本不会污染训练表。这是硬门禁，不是约定
- 缺失的标签**留空，不补零**
- 未通过完整门禁（特征重建 + 内部域 + 网格 + 求解 + 读结果）的目录，**不得当作训练数据**
- 失败的 run 目录调试完就删，避免和成功样本混淆（批量跑时 §11 会自动删，并把报告存进 `_batch/failures/`）

## 11. 批量跑：三步 —— 生成数据 → 放进 `Variables/` → 跑

### 第 1 步：在 `数据生成/` 生成采样表

数据**不由本程序生成**，源头是 `数据生成/`（和 `自动映射/` 平级，是独立的工作区）。

```bash
cd "C:\Users\liujunxiang\Desktop\流体仿真2\数据生成"
node generate_lhs.mjs        # 固定种子 20260921，产出 3200 组拉丁超立方
```

产出在 `数据生成/outputs/七变量拉丁超立方采样_3200组.xlsx`，工作表 `LHS样本`。

**采样上下界和生成规则见 [数据生成/README.md](../数据生成/README.md)**（`c`/`e` 是基准值的 ±5%，
`phi` 5~11°，`Dmax` 179.9~193.9，`bm` 7~8，`ds` 37.152~49）。⚠️ **`alpha_deg` 写的是全锥角**：
半锥角 10°~20° 必须写成 `alpha_deg = 20~40`，不能直接填 10~20。

### 第 2 步：把表放进 `自动映射/Variables/`

表格格式：**第 1 行表头，第 1 列是 `样本序号`**，其余列是七个设计变量。
列**按表头名字**匹配，顺序随便放；**可以只放一部分**（比如先放 2 行试跑）。
`Variables/` 下可以放多份表，会自动合并并检查编号不撞车。

### 第 3 步：跑

```bash
cd "C:\Users\liujunxiang\Desktop\流体仿真2\自动映射"

# 预检（只读，不写任何盘）—— 先看要跑多少、预计多久
python scripts/Run-Batch.py

# 真跑
python scripts/Run-Batch.py --execute

# 只跑前 5 个 / 只跑指定编号 / 只跑某一份表
python scripts/Run-Batch.py --execute --limit 5
python scripts/Run-Batch.py --execute --only 3,7,12
python scripts/Run-Batch.py --execute --xlsx Variables/别的表.xlsx
```

**跑之前必须手工启动 SolidWorks 并停在空白主界面**（铁律：绝不冷启动）。
每样本约 3.5 分钟 —— 55 个约 3.2 小时，3200 个约 7.5 天。

**失败不中断**：某个样本失败会记下原因、把它的报告存进 `_batch/failures/`、删掉 run 目录、
继续跑下一个。**连续 3 个失败会主动停下** —— 那多半是 SolidWorks 掉了，
重启它、停在空白主界面，再 `--execute` 续跑。

| 想知道什么 | 看哪 |
|---|---|
| 每个样本的状态 | `working/_batch/batch_state.json` |
| 失败原因 | 上面那个文件 + `working/_batch/failures/`（含完整报告）|
| 哪些跑完了 | 再跑一次预检，会显示"已完成 N 个" |

⚠️ **新样本门禁全过、训练行落盘之后，才删掉上一个 run 目录**（"只留最新一个"）。
所以任何时刻磁盘上只有一份样本副本（约 22 MB），跑 3200 个也不会撑爆。

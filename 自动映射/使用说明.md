## 3. 跑一个样本：三条命令

把 `<run>` 换成你起的名字（会建在 `working/seven_variable_trials/<run>/` 下）。

```bash
# ① 生成样本副本（约 80 秒）
#    读：config/design_baseline_v6.json（七变量）
#    写：working/seven_variable_trials/<run>/  ← 一套 CAD 副本
./scripts/Run-OneDesign.exe . <run> config/design_baseline_v6.json

# ② 跑到求解前（约 55 秒）
#    读：上面那套副本
#    写：<run>/flow_sample.json（阶段报告）、<run>/1/（Flow 工程）
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json --execute

# ③ 求解 + 出训练行（约 1 分钟；其中 40 秒是求解本身）
#    写：<run>/training_sample.csv、outputs/training_dataset.xlsx
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json \
       --execute --resume --yes-solve --timeout-min 25
```

**每样本约 3 分 15 秒。** `<run>` 不能重名（脚本拒绝覆盖）。

⚠️ ② 的耗时**不稳**（实测 54~90 秒）：波动几乎全在 S3 开口识别那一阶段的
COM 枚举上（同样的 448 条边，跨会话能差 20 秒）。③ 不用跑 S3，所以 ③ 很稳。

**只读预检**（不写任何东西，先查环境和输入）：

```bash
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json
```

**任何一步失败**：修好原因后加 `--resume` 接着跑，**不要删目录重来**。

```bash
python scripts/Run-FlowSample.py <run> --design config/design_baseline_v6.json \
       --execute --resume [--yes-solve]
```

## 4. 你会动到的文件

| 文件 | 是什么 | 谁改 |
|---|---|---|
| `config/design_baseline_v6.json` | 一个七变量设计点 | **你**：复制一份、改数值 |
| `config/flow_physics_reference.json` | 边界条件 / 目标 / 网格 / 收敛 / 参考真值 | 只在人工工程有变化时改（见 §8）|
| `working/assembly_batch_v6/` | **V6 母版** | **谁都不许改** |
| `working/seven_variable_trials/<run>/` | 每次跑出来的副本 | 脚本 |
| `outputs/training_dataset.xlsx` | 15 列训练表（追加）| 脚本 |

## 5. 跑之前必须满足（最容易卡在这）

脚本**只「附加」到已经在跑的 SolidWorks，不冷启动它**。

| 条件 | 怎么确认 |
|---|---|
| 手工启动 SolidWorks，停在**空白主界面** | 界面上没有打开的文档 |
| **关掉全部文档** | `Ctrl+W` 逐个关 |
| **只保留一个 `SLDWORKS.exe`** | 见下 |
| 残留的 `~$` 锁文件 | **不用管**，门禁会自己清 |

**两个实例怎么办：**

```bash
tasklist /v /fi "IMAGENAME eq SLDWORKS.exe" /fo csv
```

⚠️ 窗口标题是 `NVOGLDC invisible` 的那个是**残留进程**（没有界面、不持有文档），不是你在用的那个。

## 6. 结果在哪

| 想看什么 | 看哪个文件 |
|---|---|
| 每阶段干了什么、门禁过没过 | `<run>/flow_sample.json` |
| **一行 15 列训练数据** | `<run>/training_sample.csv` + `outputs/training_dataset.xlsx` |
| 停机点 / 逐目标值 / 网格数 | `<run>/1/1.info.json` |
| **逐迭代历史**（排查收敛最有用）| `<run>/1/Goals.DAT/*.txt` |
| 冻结的工程配置 | `<run>/1/1.xmlconfig` |

**15 列里那 7 个目标值 = Flow 界面「目标图」里的「平均值」列**（不是「数值」列）。

## 7. 出问题按这个表查

| 现象 | 处理 |
|---|---|
| `A same-named document is already open` | SolidWorks 里关掉全部文档 |
| 门禁报 `SLDWORKS.exe 实例数 2` | 见 §5 |
| `CO_E_SERVER_EXEC_FAILURE` | 手工启动 SolidWorks，别让脚本冷启动 |
| `拒绝续跑：几何与磁盘不符` | 删掉 `<run>` 重新克隆 |
| 卡住不动、无报错 | 去 SolidWorks 界面看有没有弹模态框，手动关掉 |
| 目标绑不上（`NeedsSeatFaces`）| **不要**加 `--allow-partial-goals` 掩盖 —— 那是"绑不上就跳过、留空列"的降级模式 |

## 8. 辅助命令

**测试**（不需要 SolidWorks）：

```bash
python -m pytest tests/ -q          # 206 个
```

**只读探针**（任何时候都能跑，不写盘）：

```bash
python scripts/Probe-FlowLocalMesh.py       # 读人工工程的活特征（局部网格参数的唯一可靠来源）
python scripts/Probe-HumanFaces.py          # 读人工原件的面表（解 Flow 的面 ID）
python scripts/Probe-GoalValues.py          # 读 .fld 里的目标值（看 API 能拿到哪几列）
python scripts/Check-HumanReference.py      # 核对参考真值还跟不跟得上根目录 1/
```

**换机器**：整个 `流体仿真2` 目录拷过去（**别只拷 `自动映射/`**，根目录那两个硬依赖要带上），
装 `pywin32` + `openpyxl`（Python 3.12，**必须 64 位**），然后改**全项目唯一一处写死的路径**：

```python
# 自动映射/scripts/Run-FlowSample.py 第 55 行
DEFAULT_FWP = Path(r"C:\ProgramData\COSMOS Applications\Flow Simulation 2026\template\internal_water.fwp")
```

或者跑的时候加 `--fwp <你的路径>`。其余路径全部从脚本位置推导，整个目录拷到哪都能跑。

⚠️ 本机 PowerShell 执行策略是 `Restricted`，所有 `.ps1` 都跑不了 —— 所以用编译好的 `.exe`。

## 9. 其他命令行工具（`valve_mapping` 子包）

不需要 SolidWorks，纯标准库。

```bash

python -m valve_mapping validate-design config/my_design.json
python -m valve_mapping audit-flow working/baseline/1
```

## 10. 数据纪律（别绕过）

- **失败只写报告、不追加数据行** —— 崩了的样本不会污染训练表。这是硬门禁，不是约定
- 缺失的标签**留空，不补零**
- 未通过完整门禁（特征重建 + 内部域 + 网格 + 求解 + 读结果）的目录，**不得当作训练数据**
- 失败的 run 目录调试完就删，避免和成功样本混淆
